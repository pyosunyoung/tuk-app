# Handoff: 툭(Tuk) — 친구 (초대코드 · 받은 신청 · 친구 목록)

## Overview
초대코드 교환으로만 절친을 추가하는 **친구 기능** 화면입니다.

구현 범위:
1. 친구 화면 — 받은 신청 + 내 절친 목록 (10a)
2. 친구 화면 — 빈 상태 (10b)
3. 친구 추가 시트 → 내 코드 / 코드 입력 (10c)
4. 코드 입력 결과 피드백 (10d)
5. 진입점 — 홈 우상단 아바타 + 신청 배지 (10e)

선행 문서: `design_handoff_tuk_auth/README.md` (로그인 플로우), `design_handoff_tuk_presence/README.md` (지금 콜·프레즌스). 토큰과 컴포넌트는 두 문서와 동일합니다.

## About the Design Files
번들의 HTML은 **디자인 레퍼런스**입니다. **HTML/CSS를 복사해 붙이지 말고, 대상 코드베이스(Flutter)의 기존 위젯과 패턴으로 재구현**하세요. 색·타이포·간격·radius 값만 정확히 가져가면 됩니다.

## Fidelity
**High-fidelity.** 모든 수치가 최종값입니다. 기준 캔버스 iPhone 402 × 874 pt (상태바 56 / 홈 인디케이터 46은 안전영역). 논리 픽셀(pt)은 Flutter 논리 픽셀과 1:1 대응.
일러스트·이미지 없음. 모든 그래픽은 도형과 텍스트로만 구성합니다.

**기존과 동일** — auth·presence 문서의 Color / Typography / Spacing / Radius / Shadow / Touch target을 그대로 사용합니다. 새 색, 새 폰트, 새 그림자를 만들지 않았습니다.

이 기능에서 처음 쓰이는 조합만 명시합니다.

## 네비게이션 제안

### 결론: 하단 탭을 만들지 않고, **홈 우상단 프로필 아바타에서 여는 화면**으로 둡니다.

**근거**
1. **현재 앱의 목적지가 두 개뿐입니다.** 홈(프레즌스)과 친구. 탭 바는 목적지가 3개 이상일 때 값을 합니다. 둘뿐인데 탭 바를 깔면 화면 하단 56pt를 상시 점유하면서, 홈의 주 CTA("툭 띄우기")와 시각적으로 경쟁합니다.
2. **친구 기능은 저빈도입니다.** 절친 5~10명을 한 번 모으고 나면 거의 들어가지 않습니다. 매일 쓰는 "툭 띄우기"와 같은 위계에 둘 이유가 없습니다.
3. **아바타는 이미 그 자리에 있습니다.** 홈 헤더 우상단 36pt 아바타는 auth 단계부터 존재하며 현재 임시로 로그아웃이 걸려 있습니다. "내 것"(내 프로필·내 절친·설정)을 여는 자리로 쓰는 것이 자연스럽습니다.
4. **콜드스타트와 동선이 이어집니다.** 홈 콜드스타트(1b)의 "친구 초대하기"는 친구 추가 시트(10c)로 직행합니다. 두 진입점이 같은 곳으로 모입니다.

**진입 경로**
```
홈 (프레즌스)
 └─ 우상단 아바타 탭 → 친구 화면 (push, 오른쪽에서 슬라이드)
       └─ [친구 추가] → 친구 추가 시트
             ├─ 내 코드 알려주기 → 내 코드 시트
             └─ 친구 코드 입력하기 → 코드 입력 시트

홈 콜드스타트
 └─ [친구 초대하기] → 친구 추가 시트 (친구 화면을 거치지 않고 바로)
 └─ [연락처에서 찾기] → 이번 범위에서는 제거. 연락처 매칭은 만들지 않습니다.
      해당 보조 버튼은 "내 코드 알려주기"로 교체하세요.
```

**로그아웃 위치**: 아바타에 걸려 있던 임시 로그아웃은 친구 화면 안으로 옮기지 말고, 별도 설정 화면(이번 범위 밖)으로 미룹니다. 임시로 필요하면 친구 화면 우상단에 "⋯" 메뉴를 두고 그 안에 넣으세요 — 친구 목록 본문에 로그아웃을 노출하지 마세요.

### 받은 신청 알림
- **배지**: 홈 우상단 아바타에 코랄 배지 (10e). 개수 표시, 10건 이상이면 "9+". 신청 0건이면 배지 없음
- 배지 등장 애니메이션: scale 0.6 → 1, 200ms ease-out. 반복 펄스·흔들림 금지
- **푸시 알림**: "새 친구 신청이 왔어요" (보낸 사람 이름 미포함 — 수락 전에는 상대 정보를 알림에 싣지 않습니다). 탭하면 친구 화면으로 이동
- 신청을 모두 수락하거나 화면을 열어 확인하면 배지 제거. **"읽음" 개념을 상대에게 전달하지 않습니다** — 읽었는지 여부는 서버에서 신청자에게 절대 노출하지 않습니다

### 1. 친구 화면 — 메인 (10a)
**목적**: 받은 신청을 수락하고, 내 절친이 누구인지 확인하고, 새 친구를 추가한다.

**레이아웃** (세로 flex)
- 헤더: padding 8 20 12, 가로 flex gap 12
  - 뒤로가기 36×36 탭 타깃, 글리프 20/500 `#2B2926`
  - 타이틀 "친구" 20/600/-0.3 `#2B2926`
- 스크롤 영역: 좌우 padding 20, 하단 padding 120
- 하단 고정: padding 16 20 46, 배경 `linear-gradient(to top, #FBF7F1 60%, rgba(251,247,241,0))`
  - 주 CTA "친구 추가" 56 pill `#FF7A5C`, 16/600 흰색, shadow `0 4px 16px rgba(255,122,92,.28)`

**받은 신청 섹션** (신청이 1건 이상일 때만 렌더)
- 섹션 헤더: 위 margin 12, 아래 12, 좌측 padding 4. "받은 신청" 16/600 `#2B2926` + 개수 16/600 `#FF7A5C` (gap 8, baseline)
- 신청 카드 (gap 8): `#FFFFFF` / **`1px solid #FFD4C6`** / radius 16 / padding 12 12 12 16 / 가로 flex gap 12
  - 아바타 38 원 `#FFEAE2`, 이니셜 15/600 `#E85D3D` (`profileImage` 있으면 원형 클립으로 대체)
  - 이름 15/600 `#2B2926`, `flex:1`, `min-width:0`
  - **"수락" 버튼만**: padding 10 20, radius 999, `#FF7A5C`, 14/600 흰색. 높이 약 40 + 카드 padding으로 탭 영역 44 이상 확보
- 안심 문구: 위 margin 12, "그냥 둬도 괜찮아요. 상대에겐 아무것도 안 보여요" 12/400 `#8A857E` 중앙

> **거절 버튼을 두지 않습니다.** 스와이프 삭제, 오래 눌러 나오는 메뉴, "나중에" 버튼도 만들지 마세요. 무시는 아무것도 하지 않는 것이며, 그 사실이 상대에게 전달되지 않는 것이 이 기능의 핵심입니다.

**내 절친 섹션**
- 섹션 헤더: 위 margin 32 (신청 섹션이 없으면 12), 아래 12. "내 절친" 16/600 + 개수 16/600 `#FF7A5C`
- 친구 카드 (gap 8): `#FFFFFF` / `1px solid #ECE7DF` / radius 16 / padding 14 16 / 가로 flex gap 12
  - 아바타 38 원 + 이름 15/600 `#2B2926`
  - **오른쪽에 아무것도 두지 않습니다** — 온라인 여부, 마지막 접속, 함께 만난 횟수, 삭제 버튼 없음. 프레즌스 정보는 홈에서만 봅니다
- 정렬: `nickname` 가나다순
- 카드 탭: 이번 범위에서는 동작 없음 (프로필 상세는 별도 기능)

**상태**
| 상태 | 처리 |
|---|---|
| 신청 0건 | 받은 신청 섹션 전체 미렌더 (빈 카드·"신청이 없습니다" 문구 없음). 내 절친 섹션이 위 margin 12로 올라옴 |
| 신청 있음 + 친구 0명 | 신청 섹션 표시 + 내 절친 섹션은 빈 상태 카드(10b 참조) |
| 신청 0건 + 친구 0명 | 10b |
| 로딩 | 카드 형태 스켈레톤 3개 (`#FFFFFF`, radius 16, 높이 66, shimmer 없이 opacity .6 정적) |
| 네트워크 실패 | 화면 중앙에 "잠시 후 다시 시도해 주세요" 14/400 `#8A857E` + 보조 pill "다시 불러오기". 빨강·경고 아이콘 없음 |

**인터랙션 / 모션**
- "수락" 탭 → 낙관적 업데이트: 신청 카드가 opacity 1→0 + 높이 축소 200ms ease-in으로 사라지고, 내 절친 목록의 가나다 위치에 높이 0→실제 + opacity 0→1, 240ms ease-out으로 삽입. 두 섹션 개수 동시 갱신
- 토스트: "{이름}과 친구가 됐어요" 1.8초
- 수락 실패 시: 카드를 원위치 복귀 + 토스트 "잠시 후 다시 시도해 주세요."
- 신청이 모두 처리되면 받은 신청 섹션이 200ms 크로스페이드로 사라지고 내 절친 섹션이 위로 올라옴
- 당겨서 새로고침 지원, 스피너 `#FF7A5C`
- 버튼 눌림: scale 0.98 + `#E85D3D`, 120ms

**데이터 매핑**
| UI | 필드 |
|---|---|
| 받은 신청 개수 | `requests.length` |
| 신청 아바타 | `requests[].profileImage` (없으면 `nickname` 첫 글자) |
| 신청 이름 | `requests[].nickname` |
| 수락 요청 | `POST /{requests[].friendshipId}/accept` |
| 절친 개수 | `friends.length` |
| 절친 아바타 / 이름 | `friends[].profileImage` / `friends[].nickname` |

`requesterId`, `userId`는 화면에 표시하지 않습니다.

### 3. 친구 추가 시트 (10c 좌)
**형식: 바텀시트.** 선택지가 두 개뿐이고, 뒤로 친구 화면이 보이는 편이 맥락 유지에 낫습니다.

- 딤 `rgba(43,41,38,.28)`, 탭하면 닫힘
- 시트 `#FFFFFF`, radius 24 24 0 0, padding 24 20 40, shadow `0 -4px 24px rgba(43,41,38,.08)`
- 그랩 핸들 40×4 radius 999 `#ECE7DF`, 중앙, 아래 margin 20
- 제목 "어떻게 추가할까요?" 20/600/-0.3
- 메뉴 행 2개 (위 margin 16, gap 8): `#FFFFFF` / `1px solid #ECE7DF` / radius 16 / padding 18 16 / 가로 flex gap 14
  - 아이콘 타일 40×40 radius 12 `#FFEAE2`, 글리프 `#E85D3D` (좌: "코드" 15/600 텍스트, 우: "＋" 20/600)
  - 제목 16/600 `#2B2926` / 설명 13/400 `#8A857E` (세로 gap 3)
  - 우측 "›" 18/400 `#8A857E`
  - 행 1: "내 코드 알려주기" / "친구가 입력하면 바로 연결돼요"
  - 행 2: "친구 코드 입력하기" / "받은 8자 코드를 넣어보세요"
- 안심 문구 (위 margin 20): "코드로만 친구가 돼요 · 검색으로는 찾을 수 없어요" 12/400 `#8A857E` 중앙

### 4. 내 코드 시트 (10c 중앙)
**목적**: 코드를 크고 정확하게 보여주고, 복사·공유로 넘긴다.

- 제목 "내 초대 코드" 20/600/-0.3
- 설명 "이 코드를 친구에게 알려주세요" 14/400 `#8A857E` (위 margin 8)
- 코드 블록 (위 margin 20): `#FFEAE2` / `1px solid #FFD4C6` / radius 16 / padding 28 16 / 중앙 정렬
  - 코드 monospace 34/600 `#E85D3D`, 자간 6
  - 8자 고정. 혼동문자(0/O, 1/I/l) 제외는 서버가 보장하므로 클라이언트에서 가공하지 않습니다
- 버튼 행 (위 margin 16, gap 8, 각 `flex:1`)
  - "복사" 52 pill `#FFFFFF` + `1px solid #ECE7DF`, 16/500 `#8A857E`
  - "공유하기" 52 pill `#FF7A5C`, 16/600 흰색, 코랄 shadow
- 안심 문구 (위 margin 16): "코드를 아는 사람만 신청할 수 있어요" 12/400 `#8A857E` 중앙

**인터랙션**
- 복사 → 클립보드 저장 + 토스트 "코드를 복사했어요". 버튼 라벨을 "복사됨"으로 바꾸지 않습니다(원복 타이밍 관리가 필요해짐)
- 공유 → 시스템 공유 시트. 공유 텍스트: `툭에서 친구하자! 내 코드: AB3K9XQ2` + (딥링크가 준비되면) 앱 링크 1줄
- 코드 블록 롱프레스로도 복사 가능
- 코드 로딩 중: 블록은 그대로 두고 코드 자리에 `········` 를 `#FFD4C6`로 표시. 스피너 없음

**데이터 매핑**: `{ code }` → 코드 블록. 재발급 기능은 이번 범위에 없습니다(버튼을 만들지 마세요).

### 5. 코드 입력 시트 (10c 우)
**목적**: 8자를 정확히 넣고 결과를 즉시 안다.

- 제목 "친구 코드 입력" 20/600/-0.3
- 설명 "친구에게 받은 8자 코드를 넣어주세요" 14/400 `#8A857E` (위 margin 8)
- 입력 필드 (위 margin 20): `#FBF7F1` / radius 16 / padding 22 16 / 중앙 정렬
  - 테두리: 미포커스 `1px solid #ECE7DF`, 포커스 `1px solid #FF7A5C`
  - 입력된 글자 monospace 28/600 `#2B2926` 자간 5
  - 캐럿 2×32 `#FF7A5C` (깜빡임 1s)
  - 남은 자리 `····` monospace 28/600 `#ECE7DF` 자간 5
  - 실제로는 투명한 TextField 위에 이 표시를 그립니다. 자리별 박스 8개로 쪼개지 마세요 — 붙여넣기와 IME 처리가 복잡해집니다
- 확인 버튼 (위 margin 16): 56 pill
  - 8자 미만: 비활성 `#FBF7F1` + `1px solid #ECE7DF`, 16/600 `#8A857E`, 탭 불가
  - 8자 완성: 활성 `#FF7A5C`, 16/600 흰색 + 코랄 shadow (전환 160ms)
  - 요청 중: 배경 유지, 라벨 자리에 흰색 스피너, 탭 불가
- 안심 문구 (위 margin 16): "상대가 수락해야 친구가 돼요" 12/400 `#8A857E` 중앙

**입력 처리**
- 자동 대문자화, 영숫자만 허용, 8자에서 입력 차단
- 붙여넣기 시 공백·하이픈 제거 후 앞 8자만 사용
- 8자가 채워지면 키보드는 유지하되 자동 제출하지 않습니다 (오입력 시 되돌리기 어려움)
- 시트가 열리면 자동 포커스 + 키보드 표시. 시트는 키보드 높이만큼 위로 밀림

**데이터 매핑**: 요청 `{ code }` → 응답 `{ friendshipId, status }`

### 6. 결과 피드백 (10d)
모든 결과는 **동일한 다크 pill 토스트 1.8초**로 처리합니다. 실패에도 빨강·경고 아이콘·다이얼로그를 쓰지 않습니다.

| 결과 | 토스트 문구 | 시트 |
|---|---|---|
| `ACCEPTED` | "{이름}과 친구가 됐어요" | 닫힘 → 친구 목록에 삽입 애니메이션 |
| `PENDING` | "신청을 보냈어요 · 수락하면 알려줄게요" | 닫힘 |
| 없는 코드 | "코드를 못 찾았어요. 다시 확인해 주세요" | 유지 + 입력값 유지, 전체 선택 상태 |
| 본인 코드 | "내 코드예요. 친구에게 알려주세요" | 유지 |
| 이미 친구 | "이미 친구예요" | 유지 |
| 네트워크 실패 | "잠시 후 다시 시도해 주세요" | 유지 |

- 실패 시 입력 필드를 흔들거나(shake) 빨갛게 만들지 않습니다. 테두리는 포커스 코랄 그대로
- **`PENDING` 상태를 목록으로 만들지 않습니다.** "보낸 신청" 섹션, "대기 중" 배지, 취소 버튼을 만들지 마세요 — 내가 보낸 신청이 어떻게 됐는지 계속 보이면 그 자체가 압박이 됩니다. 상대가 수락하면 그때 알림과 함께 친구 목록에 나타납니다
- `ACCEPTED` 응답의 이름은 서버 응답에 닉네임이 포함될 때만 씁니다. 없으면 "친구가 됐어요"로 폴백

## 반드시 지킬 UX 원칙 (재확인)
1. **거절이 보이지 않는다** — 친구 신청에 거절 버튼, 스와이프 삭제, "나중에", 무시 확인 다이얼로그를 만들지 않습니다. 신청을 그냥 두는 것이 무시이고, 그 사실은 상대에게 어떤 형태로도 전달되지 않습니다. 읽음 여부, 신청 후 경과 시간, 응답률을 노출하지 않습니다. 보낸 신청 목록도 만들지 않습니다.
2. **자동 만료** — 친구 관계에는 만료가 없습니다. 신청도 만료시키지 않습니다("7일 후 사라져요" 같은 문구 금지). 만료는 콜과 번개에만 해당합니다.
3. **무부담** — 모든 시트와 목록에 안심 문구를 둡니다. 실패도 같은 톤으로 처리하고, 확인 다이얼로그를 띄우지 않습니다.
4. **닫힌 절친** — 전체 유저 검색, 추천 친구, 근처 사람, 친구의 친구, 연락처 매칭 UI를 **어떤 형태로도 만들지 않습니다**. 친구가 되는 경로는 초대코드 교환 하나뿐입니다. 홈 콜드스타트의 "연락처에서 찾기" 보조 버튼은 "내 코드 알려주기"로 교체하세요.

## Implementation Notes
- **HTML/CSS를 복사해 붙이지 말고, Flutter 위젯으로 재구현하세요.**
- 새 컴포넌트를 만들지 말고 기존 것을 재사용합니다: 아바타, PillButton(주/보조), 카드, 바텀시트 셸(핸들 포함), 토스트, 빈 상태 카드, 섹션 헤더(제목 + 코랄 개수).

- 일러스트·이미지 에셋 없음. 모든 그래픽은 도형과 텍스트입니다.
